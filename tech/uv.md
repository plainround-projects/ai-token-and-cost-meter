# uv

## What it is

**uv** is a fast package manager for Python written in Rust. It can create virtual environments, install packages and, as used here, *resolve* a list of requirements. Resolving means: given "I need anthropic 2.3.0", find the exact versions of every other package that anthropic needs, so that all rules agree. The result is a **lock file**: a plain list of every package at an exact version.

## Why this repository uses it

Choosing the exact versions of ~40 packages by hand is not realistic, and pip's resolver is slower. uv does the resolving and writes the lock file, and from then on only plain `pip` is needed to install it. That keeps the install path simple (everyone has pip) and keeps the one-off tool (uv) out of the daily workflow.

## Where it appears

| File | What it does with this technology |
| --- | --- |
| `requirements.lock` | header comment records the `uv pip compile` command that produced it |
| `requirements-dev.lock` | same, with `--extra dev` |

## How it works underneath

A resolver reads each package's metadata (the `Requires-Dist` lines in its `METADATA` file) to learn what that package needs, then looks for one version per package that satisfies every rule at once. When two packages need different ranges of a third, it searches until a compatible version is found or reports a conflict. uv does this with a fast compiled implementation and a shared cache.

Hashes come from the package index: for each chosen version, uv records the SHA-256 hash of every downloadable file (wheels and source archive). `--universal` makes uv resolve for several platforms at once and attach environment markers where the answer differs.

## Walkthrough of this repository's use

Both lock files begin with a comment that records exactly how they were made. This is the whole of the repository's contact with uv.

`requirements.lock` (what the program needs to run), first lines:

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --generate-hashes --universal --python-version 3.12 -o requirements.lock
annotated-types==0.8.0 \
```

`requirements-dev.lock` (what the program needs to run **plus** the tools for tests and checks), first lines:

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --extra dev --generate-hashes --universal --python-version 3.12 -o requirements-dev.lock
annotated-types==0.8.0 \
```

The command in the second line, word by word:

- `uv pip compile` is the uv sub-command that reads requirements and *writes out* a fully resolved list; it does not install anything.
- `pyproject.toml` is the input: it names the project's direct dependencies (`dependencies = [...]`).
- `--extra dev` (only in the dev file) also includes the optional group `dev` from `[project.optional-dependencies]`: pytest, ruff, mypy and the other tools.
- `--generate-hashes` writes the SHA-256 hash of every downloadable file under each pinned package, which is what `pip install --require-hashes` checks.
- `--universal` produces one file that works on every operating system and Python version in range, instead of a file tied to the machine that ran the command. Packages that are only needed on some platforms are written with a marker such as `; sys_platform == 'win32'`.
- `--python-version 3.12` resolves for Python 3.12 (the oldest version the project supports), so the file works on 3.12 and newer.
- `-o requirements.lock` is the output file.

To refresh the files, you run those commands again. The Makefile has no target for it; the lock files are changed deliberately, in a commit of their own.

## Try it yourself

1. The uv installed on your computer. (The lock files were generated with the uv of the day they were made; the flags used are stable.)

```bash
uv --version
```

What you should see (captured from this repository):

```text
uv 0.11.2 (02036a8ba 2026-03-26 aarch64-apple-darwin)
```

2. The recorded command, straight from the file.

```bash
head -3 requirements.lock
```

What you should see (captured from this repository):

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --generate-hashes --universal --python-version 3.12 -o requirements.lock
```

3. The flags used in the recorded command exist and are documented in uv itself.

```bash
uv pip compile --help | grep -E -- '--(generate-hashes|universal|python-version|extra|output-file)' | head -8
```

What you should see (captured from this repository):


## Mistakes people make

- **Editing a lock file by hand.** The hashes will no longer match. Change `pyproject.toml` and compile again.
- **Compiling on one platform without `--universal`.** The file would list only the packages that platform needs, and break on another.
- **Forgetting `--extra dev` for the dev file.** The test and lint tools would be missing, and `make test` would fail.
- **Installing with uv in the daily workflow and with pip in CI.** Both read the same lock file; the Makefile uses pip so there is a single path.

## Check yourself

1. What does `uv pip compile` produce?

   *Answer:* A file listing every package the project needs at an exact version.

2. What does `--generate-hashes` add?

   *Answer:* The SHA-256 hash of each downloadable file, so pip can verify what it installs.

3. Why is `--python-version 3.12` there?

   *Answer:* To resolve for the oldest supported Python so the file works on all later ones.

4. What does `--universal` do?

   *Answer:* Makes one file that works on any platform, using markers for platform-specific packages.

5. Does the Makefile call uv?

   *Answer:* No. uv only generated the lock files; installs use pip.
