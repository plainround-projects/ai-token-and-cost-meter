# Lock files (requirements.lock and requirements-dev.lock)

## What it is

A **requirements file** is a text file that lists packages for `pip install -r`. A **lock file** is a requirements file with a strict rule: *every* package is listed, including the packages your packages depend on (called *transitive* dependencies), each at one exact version, each with the hashes of its files. Nothing is left for pip to decide.

A **dependency** is a package your code needs. A **direct** dependency is one you named yourself; a **transitive** one is needed by something you named. Version `==0.28.1` means exactly that version. A **hash** is a fixed-length fingerprint computed from a file's bytes; any change to the file changes the fingerprint.

## Why this repository uses it

Two installs of "the same" project made a month apart should run the same code. A range such as `httpx>=0.28` cannot promise that; a lock file does. The hashes add a second promise: the bytes pip installs are the bytes that were reviewed when the lock was made. This matters here because the numbers in the README (token counts, costs, test counts) were measured against these exact versions.

## Where it appears

| File | What it does with this technology |
| --- | --- |
| `requirements.lock` | runtime packages only |
| `requirements-dev.lock` | runtime packages plus test and check tools; the one `make install` uses |
| `Makefile` | the stamp rule depends on `requirements-dev.lock` and installs it with `--require-hashes` |
| `.github/workflows/ci.yml` | `make audit` checks these pinned versions for known vulnerabilities |

## How it works underneath

**Why file names, not just names, are hashed.** A package version is published as several files. pip picks the one that fits your computer, so the lock lists all of them and pip accepts any one that matches.

**All or nothing.** In hash-checking mode pip refuses a file with no hash, a package with no exact version, and a dependency it would have to add on its own. If something is missing from the lock, the install stops with an error that names it, instead of quietly fetching something unreviewed.

**Environment markers** use a small language (`sys_platform == 'win32'`, `python_version < '3.13'`). pip evaluates them on your computer and skips lines whose marker is false.

## Walkthrough of this repository's use

The first lines of `requirements.lock` (the first package and the start of the second):

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --generate-hashes --universal --python-version 3.12 -o requirements.lock
annotated-types==0.8.0 \
    --hash=sha256:13b2beaad985e05e2d6407ee4c4f35590b11f8d693a258a561055cac8f64cab7 \
    --hash=sha256:f072f4d804ea359e4eaf198b1af7a8b0943881a87f31bb764f8bf219bb9419e0
    # via pydantic
anthropic==2.3.0 \
    --hash=sha256:aa6a3984f9276f307933d42dc6f58b6efc821a5ecafbc8d1bb5993a066767622 \
    --hash=sha256:edfdea1e3fa7b3ce25df1511953408b2f03bfa61eb6f6268f766101a9e18ad53
    # via ai-token-and-cost-meter (pyproject.toml)
anyio==4.15.1 \
```

Line by line:

- `# This file was autogenerated by uv ...`: a comment (lines starting with `#` are ignored by pip). It says a tool wrote the file and records the command; see `uv.md`.
- `annotated-doc==0.0.5 \` (the name changes with the package): the requirement. A name, `==`, an exact version, and a backslash, which tells pip "the requirement continues on the next line".
- `--hash=sha256:...` lines: one per downloadable file of that version. Each is the algorithm (`sha256`), a colon, and 64 hexadecimal digits. pip downloads a file, computes its SHA-256 and requires a match with one of these lines. A package usually has several files: one wheel for each operating system and Python version, plus the source archive.
- `# via fastapi`: a comment that says why this package is here. `via pyproject.toml` means the project asked for it directly; `via X` means package X needs it. A multi-line `# via` lists several packages.
- A line such as `colorama==0.4.6 ; sys_platform == 'win32' \` adds an *environment marker* after a semicolon: install this only where the condition is true. This is how one file serves every platform.

**`requirements.lock`** pins 20 packages: what the program needs to run. **`requirements-dev.lock`** pins 61: the same plus the tools for tests, lint, types, import rules and the audit. The Makefile installs the dev file.

## Mistakes people make

- **Pinning only direct dependencies.** A new release of a transitive dependency could change behavior. The lock lists all of them.
- **Mixing versions by hand.** Editing one version invalidates its hashes and the install stops with a hash mismatch.
- **Reading the lock as documentation.** It lists what is installed, not why you chose it. The reasons are in `pyproject.toml`.
- **Forgetting that `pyproject.toml` and the lock can drift.** The Makefile's stamp rule depends on both files, so changing either one makes the next `make` reinstall.

## Check yourself

1. What is a transitive dependency?

   *Answer:* A package that one of your dependencies needs.

2. What does a `--hash=sha256:` line let pip check?

   *Answer:* That a downloaded file is exactly the one that was locked.

3. What does `; sys_platform == 'win32'` mean?

   *Answer:* Install this package only on Windows.

4. Why does the lock list several hashes for one package?

   *Answer:* A version ships several files (per platform and Python version); any one may be needed.

5. What are `# via` comments for?

   *Answer:* To show which package pulled this one in, or that `pyproject.toml` asked for it directly.
